This page lists the changes in each Priompt release, newest first. Version numbers follow the server repository (`github.com/priompt/priompt`); the other repositories have their own tags, listed with the release they shipped in.

## v0.7.3

Released 2026-10-18. Ships with `proto`, `db-adapters`, `auth`, and `cli` v0.7.1, `priompt-sdk` 0.7.1, and `@priompt/client` 0.1.1.

:::warning Upgrading Docker volumes
The image now runs as uid 10001 instead of root. Before you start it on a volume that an older image wrote, run `docker run --rm -v <volume>:/data alpine chown -R 10001:10001 /data`. See [Install with Docker](/installation/docker).
:::

**Security.** These advisories are fixed in this release:

- [GHSA-6rcm-p855-wm85](https://github.com/priompt/priompt/security/advisories/GHSA-6rcm-p855-wm85) (high): the NATS broker token gave every holder full rights across orgs. Subscribers now use their own API token, limited to their org.
- [GHSA-v49j-3wx9-7frw](https://github.com/priompt/priompt/security/advisories/GHSA-v49j-3wx9-7frw) (medium): addresses with dots could share a NATS subject. Subjects now percent-encode segment bytes outside `[A-Za-z0-9_-]`. Use the SDK releases above.
- [GHSA-v7x7-f94j-4x29](https://github.com/priompt/priompt/security/advisories/GHSA-v7x7-f94j-4x29) (medium): `DiffCommits` didn't check that both commits belong to the requested prompt.

**Server and `priompt` CLI**

- **Docker**: the database lives on the `/data` volume with the default command, and the image runs as a non-root user ([#12](https://github.com/priompt/priompt/issues/12)).
- **Merge events**: `MergeBranch` into `main` notifies subscribers with the verdict ([#13](https://github.com/priompt/priompt/issues/13)).
- **TLS flags**: `-tls-cert` without `-tls-key`, or the reverse, stops the server ([#14](https://github.com/priompt/priompt/issues/14)).
- **`watch`**: logs the NATS URL as `nats://***@host` ([#15](https://github.com/priompt/priompt/issues/15)).
- **`put` and `import`**: validate, and commit to `main`; identical content is a no-op ([#16](https://github.com/priompt/priompt/issues/16)).
- **`publish`**: prints `unchanged … already served; no change event sent` for a no-op, and still sends the event when the cache clear fails ([#17](https://github.com/priompt/priompt/issues/17)).
- **Encryption key**: a missing or wrong `PRIOMPT_ENCRYPTION_KEY` stops the server at startup ([#18](https://github.com/priompt/priompt/issues/18)).
- **Semantic diff**: a trailing newline doesn't change the verdict. The demo prompt now ends with a newline, so its version hash is `22e5cc10ac0f` instead of `e345dcf74d01` ([#19](https://github.com/priompt/priompt/issues/19)).
- **`init` on Windows**: prints PowerShell syntax ([#20](https://github.com/priompt/priompt/issues/20)).
- **Template files**: the CLI strips a UTF-8 byte-order mark, converts CRLF to LF, and rejects UTF-16 ([#21](https://github.com/priompt/priompt/issues/21)).
- **Dev seed script**: `seed-dev.sh` runs on Linux and macOS and from any directory ([#22](https://github.com/priompt/priompt/issues/22)).
- **Branch publishes**: republishing a branch tip's content is a no-op ([#23](https://github.com/priompt/priompt/issues/23)).
- **`ListPrompts`**: an empty prefix with an org-scoped token lists that org ([#24](https://github.com/priompt/priompt/issues/24)).
- **Audit log**: lines for JWT callers include `sub` ([#25](https://github.com/priompt/priompt/issues/25)).

**Modules**

- **`auth` v0.7.1**: a `#` after the first field starts a comment in tokens, clients, and groups files; two org words or two expiries on a line is an error ([auth#2](https://github.com/priompt/auth/issues/2)).
- **`proto` v0.7.1**: an edit to the last line is one `replace` hunk ([proto#5](https://github.com/priompt/proto/issues/5)); `buf lint` passes ([proto#3](https://github.com/priompt/proto/issues/3)); `created_at` is documented as `RFC3339Nano` ([proto#4](https://github.com/priompt/proto/issues/4)).
- **`cli` v0.7.1 (`promptctl`)**: `diff -fail-on` exits `1` on a matching verdict, and added prompts read `new` ([cli#3](https://github.com/priompt/cli/issues/3)); `-tls` without `-ca-cert` trusts the system CA roots ([cli#4](https://github.com/priompt/cli/issues/4)); `promote` returns to the branch you started on ([cli#5](https://github.com/priompt/cli/issues/5)).
- Every repository now carries the Apache-2.0 `LICENSE` file.

**SDKs**

- **`priompt-sdk` 0.7.1**: `subscribe(..., reload=)` applies a reload policy to the cache ([python-sdk#3](https://github.com/priompt/python-sdk/issues/3)); a wrong broker token or an unreachable broker raises `ConnectionError` ([python-sdk#4](https://github.com/priompt/python-sdk/issues/4)); reads `PRIOMPT_TOKEN` ([python-sdk#5](https://github.com/priompt/python-sdk/issues/5)); new subject encoding.
- **`@priompt/client` 0.1.1**: uses `@nats-io/transport-node` ([js-sdk#5](https://github.com/priompt/js-sdk/issues/5)); a wrong broker token rejects at once with `Authorization Violation` ([js-sdk#6](https://github.com/priompt/js-sdk/issues/6)); reads `PRIOMPT_TOKEN` ([js-sdk#7](https://github.com/priompt/js-sdk/issues/7)); new subject encoding. Not on npm yet; see [Known issues](./known-issues.md).

**Web UI** (from the `ui` repository's `main`)

- **Check impact** returns the real verdict ([ui#4](https://github.com/priompt/ui/issues/4)); the commit dialog saves the extended description ([ui#5](https://github.com/priompt/ui/issues/5)); **Create branch** keeps the selected prompt ([ui#6](https://github.com/priompt/ui/issues/6)).
- Branches beyond the four conventional names can be shown by name ([ui#7](https://github.com/priompt/ui/issues/7)), and the Rollback list can roll forward, with **Undo** after a rollback ([ui#8](https://github.com/priompt/ui/issues/8)). Both are partial until [priompt#45](https://github.com/priompt/priompt/issues/45).
- A branch switcher, **Compare** buttons, navbar search inside a namespace, and a namespace **History** tab that lists prompts ([ui#9](https://github.com/priompt/ui/issues/9)); assorted cosmetic fixes ([ui#10](https://github.com/priompt/ui/issues/10)).

## v0.7.2

Released 2026-10-17.

- **Version reporting**: A binary built with `go install github.com/priompt/priompt/cmd/priompt@v0.7.2` reports its module version in `priompt version` and in the startup log line. A `go build` in a checkout reports the git commit. Release builds still stamp both through `-ldflags`. In v0.7.1, `go install` builds reported `dev`.

## v0.7.1

Released 2026-10-17.

- **Public Go modules**: The server is published as `github.com/priompt/priompt` and requires the published modules, with no `replace` directives. `go install github.com/priompt/priompt/cmd/priompt@latest` works without a clone.
- **Module releases**: These modules were tagged `v0.7.0` the same day, under their public paths:
  - `github.com/priompt/proto`: the gRPC contract, the JWT claims, validation, and the semantic diff.
  - `github.com/priompt/db-adapters`: the SQLite and PostgreSQL storage engine.
  - `github.com/priompt/auth`: `priompt-auth` and the `authn` package the server uses.
  - `github.com/priompt/cli`: `promptctl`.

## v0.7.0

Released 2026-10-17. The first tagged server release, and the first published container image.

- **Container image**: Tagging `v*` publishes <Var name="dockerImage" /> for `linux/amd64` and `linux/arm64`, with provenance and an SBOM. The release runs only after the test workflow passes.
- **Build info**: New `priompt version` command. `serve` logs its version and commit at startup, and the metrics endpoint exposes `priompt_build_info{version,commit,goversion}`.
- **Server-side versioning**: Each prompt has a commit history with branches, merges, history, commit diffs, pinning by ref, and rollback. Change events carry the semantic diff verdict.
- **License**: The server and both SDKs are licensed under Apache-2.0.

The client SDKs were prepared for their registries in the same cycle:

- **Python SDK** `0.7.0`: published as <Var name="pypiName" />. It imports as `priompt_sdk`.
- **Node SDK** `0.1.0`: published as <Var name="npmName" />.

## Earlier versions

Versions before v0.7.0 weren't tagged. They added these features:

| Version | Added |
| --- | --- |
| v0.6 | Token expiry and rotation, mTLS, Prometheus metrics and the audit log, per-org rate limits, backup and restore, schema migrations. |
| v0.5 | PostgreSQL storage, the shared Redis cache, and org-scoped tokens. |
| v0.4 | Change events over embedded NATS, and TTL sync for subscribers. |
| v0.3 | `promptctl`: `commit`, `diff`, `log`, `promote`, `push`, and `pull`. |
| v0.2 | Client (L1) and server (L2) caches with a TTL, keyed on the version hash. |
| v0.1 | The gRPC server, the Python client, and prompt validation. |

For what's planned next, see [Status and roadmap](../roadmap.md).
